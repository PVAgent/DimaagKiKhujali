    Why this was recommended

      Architecture advisory only. Validate availability, platform limits, measured workloads, security policies, and cost before production deployment.

      Three questions first. Optimization comes afterward.

      A human-readable decision tree. One solution may combine session state, durable checkpoints, knowledge retrieval, and a cache.

      Q1. Where is the trusted, up-to-date answer?
      If it must be the latest live business value → query the system of record.
      ↓ If agent-held state or reusable information is appropriate
      Q2. How long must it remain available?
      One execution
      Working memory / bounded context
      One conversation
      Session state (add checkpoint for recovery)
      Across conversations
      Long-term memory
      ↓ If long-term, determine content type
      Knowledge / preferences
      Semantic memory or governed RAG repository
      Past runs / results
      Episodic memory and event history
      Approved procedure
      Procedural registry / versioned skills
      ↓ Independently evaluate optimization
      Q3. Is the same answer reused frequently, expensive to obtain, and safe to be stale?
      If yes → optional cache with TTL, version keys and invalidation. Otherwise direct retrieval.
      ↓ Finally
      Choose storage using shape + lookup + scale + governance
      Key-value • relational • vector index • object store • Git • authoritative source
      Important: LLM inference KV cache is an internal model-serving optimization. It should not be confused with an application's Redis cache or with persistent agent memory. Likewise, a vector index is a retrieval mechanism, not a universal source of truth.

      Rules behind the advisor

      The rules are deterministic and work entirely in your browser. No answers are sent to a server or stored by this page.

      RULE A

      Purpose before platform

      First distinguish authoritative data, transient context, session continuity, checkpoints, learned information, and versioned procedures.

      RULE B

      Shortest safe lifespan

      Use the shortest retention window that meets the user need. Never promote all session content to long-term memory automatically.

      RULE C

      Cache is an overlay

      High frequency alone is not enough. Also evaluate reuse, stale-answer risk, cost, versioning, and invalidation.

      RULE D

      Durability is independent

      A short-lived workflow may still need durable checkpoints. A long-lived memory must have a proper persistent backing store.

      RULE E

      Choose retrieval by shape

      Exact key uses indexed KV lookup; structured data uses queries; related concepts use semantic or hybrid search.

      RULE F

      Access control before search

      Enforce tenant, user and entitlement boundaries before any retrieval. Filtering after vector search is not a sufficient security boundary.
